# 월례회 성적 1차 정책과 베타 적용 계획

## 확정 정책 (2026-10-30 후속 승인)

이 문서는 기존 로컬 구현 보고서 이후의 사용자 확정 사항을 기록한다. 당시 보고서는 변경하지 않는다.

- 타수 없이도 참가·성적 미입력으로 저장한다. 0타·불참으로 추정하지 않는다.
- 입력 완료자만 순위를 계산한다. 미입력자가 있으면 **입력된 성적 기준 순위**임을 안내한다.
- 경기별 비고를 사용한다.
- 이전 수동 참가자는 명시적으로 재선택해 다른 달에 재사용할 수 있다. 이름으로 자동 연결하지 않는다.

동호회별 월 1회, 18홀 양의 정수 총타수, 남녀 통합, 낮은 타수 우선, 공동 순위 1·2·2·4와 동타 내 가나다순을 유지한다. 회장·부회장이 별도 승인 없이 저장·수정하고 현재 회원만 조회·다운로드한다. 수동 참가자는 ‘동호회 미가입회원’으로 표시하며 계정·가입 관계·조회 권한을 생성하지 않는다. 스냅샷·안정된 참가자 식별자로 과거 기록·동명이인을 보호한다.

월별/연간 조회와 PDF/JPG·A4 가로/세로를 제공한다. 평균 비교·대회·전체 동호회 순위·개인 최저타·최근 비교·메달·OCR은 후속 범위다.

## 배포 구조

`npm ci` → `npm run build`의 prebuild가 고정 버전 PDF.js 정적 자산을 준비한다. 생성 자산은 Git에서 제외하되 배포 public 디렉터리에 포함한다. 브라우저는 동일 출처의 PDF.js를 사용한다. 서버 PDF 코드는 Node.js 경로에만 포함되며 Noto TTF는 Next output tracing에 명시한다. 글꼴 출처/가공/OFL은 `src/assets/fonts/`에 포함한다. Python·Windows 글꼴·시안 서버·유료 변환 API는 필요 없다.

다운로드는 서버에서 현재 회원 자격을 재확인해 저장 자료만 출력한다. `private, no-store`와 `Vary: Cookie`를 유지한다. JPG는 같은 PDF를 브라우저에서 페이지 단위 300dpi로 변환한다. 미저장 초안·공개 Storage 파일을 사용하지 않는다.

Vercel 공식 문서의 함수 응답 제한은 4.5MB, 일반 함수 번들은 250MB다. 검증 PDF 약 3.1MB는 응답 제한보다 작다. 전체 TTF를 포함하므로 자료가 크게 늘면 파일 크기·생성 시간과 메모리를 다시 확인해야 한다. JPG 자체는 서버 응답에 포함하지 않지만 페이지별 다운로드마다 PDF를 재조회하므로 전송량과 브라우저 메모리를 사용한다. Free 요금제를 유지하며 실호스팅 실행 성공을 보장하지 않는다.

공식 근거: https://vercel.com/docs/functions/limitations

## 최소 베타 확인과 자료 정리

- 실제 회원 권한으로 월별/연간 조회·다운로드, 회장/부회장만 입력 진입, 외부인·다른 동호회 접근 거절을 확인한다. 타인의 실제 월례회 자료를 수정하지 않는다.
- 저장·수정 확인이 필요하면 별도 승인된 시험용 동호회/가상 계정과 식별 가능한 시험 연월을 사용한다. 참가 신청을 출석으로 가져오지 않는다. 만든 sheet/person/request ID와 회원 관계 ID를 기록한다.
- 시험 정리는 기록한 시험 sheet의 행→sheet, 다른 경기에서 참조하지 않는 시험 person, 해당 시험 요청 이력 및 새로 만든 시험 관계만 대상으로 한다. 기존 회원·다른 월·공유 person은 제거하지 않는다. 정리 전/후 범위를 확인하고 기존 통제 절차로 진행한다. 이번 준비에서는 원격 시험 자료를 만들거나 정리하지 않았다.
- 한글 PDF와 JPG 실제 다운로드, A4 방향·페이지 구성·전체 명단, 응답 크기·시간·함수 로그·브라우저 오류·private/no-store를 확인한다. 특히 65명 연간 출력으로 호스팅 실행 한도를 확인한다.
- 기존 특별 기록, 가입, 문의 진입만 좁게 확인한다.

## 실패 대응

SQL 트랜잭션 실패는 전체 rollback 후 원인을 검토한다. 실패한 migration을 이력 repair로 완료 처리하지 않는다. 코드 빌드/확인 실패 시 베타 별칭을 기존 배포에 유지한다. 전환 후 오류면 저장 중인 사용자 영향을 확인하고 기록을 보존한 뒤 기존 베타 배포로 별칭을 복구한다. 신규 private 테이블/기록은 남겨 두고 최소 forward fix를 준비한다. 적용 후 DB를 역으로 drop하거나 새 성적 자료를 지워 복구하지 않는다. 개인정보 트리거 관련 문제도 증거와 자료를 보존하고 승인된 최소 수정으로 대응한다.
